Deep Signal is built around a full-screen WebGL descent. Signal Strike depends on a desktop browser, pointer lock, a mouse, and keyboard input. Both could easily become empty canvases for crawlers, reduced-motion users, unsupported devices, or anyone whose graphics initialization fails.

The solution in this repository is not a generic “enable JavaScript” message. Each experience contains a complete reading version in the initial HTML.

Five failure layers

The pages account for different reasons the interactive version might not run:

  • JavaScript is disabled.
  • The browser lacks required WebGL features or an asset fails to load.
  • The user requests reduced motion.
  • The screen or input device does not support the interaction model.
  • Initialization stalls and the intro overlay would otherwise trap the page.

These are separate states. Treating them as one boolean hides useful choices—for example, a phone can still receive the full reading version even though the desktop game cannot sensibly run.

Write the fallback as primary content

`src/lab.html` and `src/game.html` contain substantial `

` elements, not content injected after feature detection. That has three benefits:

  • The explanation exists before scripts execute.
  • Search engines and assistive technology receive meaningful structure.
  • A graphics failure can reveal existing content instead of constructing an emergency interface.

The Lab article explains the authored crystals, Draco geometry, KTX2 matcaps, interactions, adaptive quality, and persistent keystone. The Arena article documents modes, controls, networking, procedural sound, and hardware requirements.

Let capability decide visibility

The layout starts with both the experience shell and reading content available in the document. CSS and runtime classes decide which presentation is visible. Inside each layout, a `

<noscript><style>
  .lab-intro, .lab-hud, .labfx { display: none !important; }
  .lab-fallback { display: block !important; }
</style></noscript>

The exact selectors differ between Lab and Arena, but the principle is the same: the no-script path cannot remain behind a boot veil.

Fail closed at runtime

JavaScript errors are harder because JavaScript has already hidden or transformed parts of the page. The runtime therefore uses explicit failure classes and hard intro-release timers. In `lab3d.js`, an asset or initialization error routes to the no-3D presentation. The intro also has a timed escape hatch so a stalled loader does not permanently cover the article.

The smoke harness tests honesty markers and fallback conditions rather than only checking for a 200 response. That matters: a page can load successfully while remaining unusable.

What remains imperfect

  • The interactive and reading presentations duplicate some information and must be kept synchronized.
  • A full article is heavier than a short fallback, though it delivers more value.
  • Feature detection cannot predict every slow or unstable GPU.
  • Pointer-lock games still need a fundamentally different mobile interaction model; the fallback does not create one.

The fallback is successful when it is useful on its own. It should not feel like the broken version of the “real” page.
