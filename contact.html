Good questions to send

The work on this site is deliberately documented so readers can evaluate it without relying on marketing claims. If you have found something unclear, undocumented, or worth discussing, that is exactly the kind of message worth sending:

  • Questions about how a specific part of a browser project was built — the engineering notes point back to real decisions, and the source is in the repository.
  • Feedback on a field note: something that was omitted, a measured limit that does not match your own findings, or an approach you have taken differently.
  • Design observations about the AXON interface study — the showcase is meant to be evaluated, not just viewed.
  • Accessibility issues on any page — reproduced with device type and browser version, if possible.

What to expect

stackwith.me is maintained by one person, not a staffed support organisation. There is no guaranteed response time. Clear reproduction steps, page URLs, browser details, and screenshots make technical questions much easier to answer.

There is no public phone-support line and no round-the-clock coverage. Email is the clearest route because it creates a useful paper trail for technical and privacy requests.

About the workshop

stackwith.me publishes browser experiments and practical engineering notes. Articles include source walkthroughs, worked examples, and design exercises. AI assists with writing and implementation; the editorial method explains the evidence and correction process.

The site publishes at https://stackwith.me. The source repository is available on GitHub.
